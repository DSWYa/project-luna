🌑 PROJECT LUNA
The Tech Bootcamp Where You Build a Lunar Base
Year: 2042
Assignment: LUNA-1 Digital Infrastructure
Role: Junior Systems Engineer
Location: Earth Mission Control
Construction of humanity's first permanent lunar research station is nearly complete.
The habitat modules are sealed.
The solar arrays are deployed.
The communications equipment is installed.
There is only one problem.
The digital infrastructure does not exist yet.
That's your job.
Over the next ten missions, you will build the systems required to bring LUNA-1 online.
You will work with real technologies used throughout IT, software development, cloud infrastructure, DevOps, automation, cybersecurity, data, and artificial intelligence.
By the end of Project LUNA, you will have worked with technologies including:
- Linux
- Virtual machines
- Networking
- SSH
- Git and GitHub
- Python
- Bash and PowerShell
- SQL
- PostgreSQL
- REST APIs
- HTML, CSS, and JavaScript
- Docker
- GitHub Actions
- Monitoring
- Webhooks and automation
- AI systems
- Kubernetes
You will not learn these technologies as isolated tutorials.
Every skill exists because LUNA-1 needs something built.

How Project LUNA Works
Every mission follows the same basic cycle:
BRIEFING → LEARN → LABS → BUILD → INCIDENT → VALIDATE → COMMIT
BRIEFING
You receive a new operational requirement from Mission Control.
LEARN
The Academy material introduces the concepts and tools required for the mission.
LABS
Small guided exercises allow you to practice individual skills.
BUILD
You receive a project specification.
Unlike the labs, projects do not tell you every command to enter.
You must decide how to accomplish the objective.
INCIDENT
Something breaks.
You must troubleshoot it.
Hints are available, but try solving the incident yourself first.
VALIDATE
Testing material helps verify that your system meets the mission requirements.
COMMIT
Your completed work is documented and eventually added to your own GitHub portfolio repository.

Rules of the Program
Rule 1 — Type the commands yourself
Copying commands may get you through a tutorial.
Typing them helps you remember them.
Whenever practical, type commands manually.
Rule 2 — Read errors
Errors are not failures.
Errors are information.
Read the message before searching for a solution.
Rule 3 — Break things
You are working inside virtual machines and local lab environments.
Experiment.
Change things.
Break things.
Then figure out why they broke.
Rule 4 — Don't immediately open the solution
Incident folders may contain hints and solutions.
Try troubleshooting on your own first.
A good rule is:
Spend at least 15 minutes investigating before opening Hint 1.
Rule 5 — Keep notes
Engineers document what they build.
Create notes throughout the course.
Record:
- Commands you frequently use
- Problems you encounter
- Solutions
- Screenshots
- Architecture changes
- Things you want to research later

What You Need
Project LUNA is designed around free tools.
You should have:
- A Windows, macOS, or Linux computer
- At least 8 GB of RAM recommended
- Approximately 40 GB of available storage
- Internet access
- A GitHub account
- Administrator access to your computer
Most labs assume a Windows host computer, but the technologies themselves are cross-platform.
