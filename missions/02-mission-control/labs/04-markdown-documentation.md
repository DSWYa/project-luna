# LAB 04 — MARKDOWN DOCUMENTATION

## Objective

Create documentation that another engineer could actually read.

Inside `luna-git-training`, create:

```text
docs\luna-1.md
```

Your document must contain:

- A level-1 heading.
- At least two level-2 headings.
- A bullet list.
- A numbered list.
- Inline code.
- A fenced code block.
- A table.
- At least two checkboxes.

Suggested subject:

**LUNA-1 Command Server Operations Guide**

Include useful Mission 01 information such as:

- Server purpose.
- SSH port.
- HTTP port.
- Commands used to check services.
- Basic troubleshooting order.

Commit and push the documentation.

Open it on GitHub and verify that the Markdown renders correctly.

---

# Reflection

Good documentation should reduce the number of questions the next engineer needs to ask.

Read your document as if you had never seen Project LUNA.

Would it still make sense?
