# MISSION 02 — LEARNING OBJECTIVES

By the end of this mission, you should be able to explain or demonstrate the following without following the walkthrough line-by-line.

---

## Git Fundamentals

- Explain the purpose of version control.
- Explain the difference between Git and GitHub.
- Explain the difference between a repository and a normal folder.
- Explain the working tree, staging area, and commit history.
- Initialize a Git repository.
- Inspect repository state with `git status`.
- Stage files with `git add`.
- Create commits with useful commit messages.
- View commit history.
- Inspect uncommitted changes.
- Explain what `.gitignore` does.

## Remote Repositories

- Explain local versus remote repositories.
- Identify a repository's `origin`.
- Clone a GitHub repository.
- Push local commits to GitHub.
- Pull changes from GitHub.
- Explain why pulling before beginning work can prevent problems.

## Branches and Merging

- Explain what a branch represents.
- Create and switch branches.
- Make independent commits on a branch.
- Merge a branch into another branch.
- Recognize a merge conflict.
- Resolve a basic text merge conflict.

## Documentation

- Create Markdown headings.
- Create lists.
- Format inline code and code blocks.
- Create links.
- Add simple tables.
- Write a useful project README.
- Document requirements and architecture.

## GitHub Workflow

- Create a repository.
- Create an Issue.
- Use an Issue to describe a unit of work.
- Close an Issue after the work is completed.
- Navigate repository commit history.

---

# Mission Completion Standard

You are ready for Mission 03 when you can:

- Create a local Git repository from scratch.
- Make multiple meaningful commits.
- Explain what changed between commits.
- Connect a local repository to GitHub.
- Push and pull successfully.
- Work on a feature branch and merge it.
- Resolve a simple merge conflict.
- Create readable Markdown documentation.
- Maintain a clean working tree.
- Explain why committing everything once at the end is poor version-control practice.

You do not need to memorize every Git command.

You should understand the lifecycle:

```text
EDIT
  ↓
STATUS
  ↓
STAGE
  ↓
COMMIT
  ↓
PUSH
```

And when moving between computers:

```text
PULL
  ↓
WORK
  ↓
COMMIT
  ↓
PUSH
```
